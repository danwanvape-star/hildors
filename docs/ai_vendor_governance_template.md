# Hildors AI 工具准入、盘点与治理模板

## 1. 使用目的

本文用于逐一审查 GPT、Grok、图像生成、视频生成、抠像、补帧、配音、转码和内容审核工具。

工具名称本身不能代表可以安全使用。相同供应商的网页个人版、团队版、企业版和 API，可能具有不同的数据、权限、计费及商用条件，必须作为不同工具条目分别审查。

在审查结论生效前：

- 只允许使用合成测试素材或取得明确内部测试授权的素材；
- 禁止上传真实付费用户的可识别人物照片、未成年人资料和身份证明；
- 禁止员工使用个人账号处理订单素材；
- 禁止把“平台能生成”理解为“允许商用交付”。

## 2. 工具资产台账

同一工具的网页端和 API 应分别编号。例如，某服务的个人网页账号不能自动继承其企业 API 的批准结论。

## 3. 准入资料清单

负责人提交工具申请时必须附上：

- 官方产品与能力说明；
- 当前服务条款、隐私政策和数据处理说明的链接及存档日期；
- 账号版本、合同主体和付款方式；
- 输入数据是否用于训练或产品改进；
- 数据默认保留期限以及能否关闭或删除；
- 子处理方和数据处理地区；
- 输入素材及生成输出的商用权利说明；
- 内容安全、投诉和侵权处理机制；
- API 密钥、成员权限、日志和费用控制能力；
- 服务故障、账号封禁和数据删除时的退出方案；
- 使用合成测试集得到的质量、成本、时延和失败率。

不能只保存网页链接。条款会变化，应保存审查时版本、截图或内部摘要及复审日期。

## 4. 数据与隐私问卷

### 4.1 输入数据

- 工具会接收哪些数据：文本、照片、视频、声音、元数据还是身份材料？
- 是否需要传入完整原图，能否使用裁剪、降采样或去标识版本？
- 是否会读取 EXIF、GPS、文件名或上传者账号信息？
- 是否允许处理人物肖像、未成年人、纪念逝者和真人声音？
- 是否禁止某些敏感或高风险用途？

### 4.2 数据使用

- 输入和输出是否用于训练、人工审核或产品改进？
- 默认行为是什么，关闭训练是否需要企业方案或额外配置？
- 设置对历史数据还是仅对未来数据生效？
- 供应商员工或承包商在什么情况下可以访问内容？
- 数据是否会用于广告、画像或与其他产品账号关联？

### 4.3 保存和删除

- 原始输入、生成结果、日志、备份分别保存多久？
- 是否支持立即删除，还是仅在固定周期后删除？
- 删除是否覆盖缓存、备份和子处理方？
- 能否按订单、任务或文件 ID 请求删除并获得结果？
- 账号终止后数据如何处理？

### 4.4 地区与传输

- 数据主要存储和处理在哪些国家或地区？
- 用户能否选择处理地区？
- 是否使用其他云服务或子处理方？
- 销售地区和用户授权是否覆盖相应传输？

上述问题没有书面答案时，工具不得用于可识别人物及 L3 订单。

## 5. 权利与商用问卷

- 用户上传内容的所有权是否保持不变？
- 供应商获得何种许可，范围和期限是什么？
- 生成结果是否允许商业使用、转售、再分发和嵌入硬件产品？
- 免费、个人、团队、企业和 API 方案的权利是否不同？
- 输出是否可能受第三方权利、素材库许可或水印限制？
- 是否要求展示来源、保留标识或禁止移除水印？
- 供应商是否提供版权、侵权投诉或赔偿机制？适用条件是什么？
- 使用人物、商标、音乐、声音和受保护角色时有哪些额外限制？
- 模型输出能否作为用户永久使用的已交付文件？

商用结论必须对应具体账号和服务方案，不能以营销页面的一句“可商用”作为完整依据。

## 6. 安全与账号问卷

- 是否支持企业账号、单点登录、多因素认证和成员离职回收？
- API 密钥能否按环境、工作流和人员拆分？
- 是否支持使用量、费用、来源 IP 和权限范围限制？
- 是否有操作日志、导出记录和异常登录告警？
- 网页端是否允许成员下载原始素材，能否限制？
- 回调是否签名，是否支持重放防护和幂等查询？
- 供应商是否公布安全事件通知和响应流程？
- 密钥泄露、员工离职或工具停用时，多久可以完成撤销？

如果工具只能使用共享账号且没有操作日志，最高只能批准为低风险内部测试，不应进入真实订单生产。

## 7. 质量与运营问卷

- 当前工具最适合哪些任务，不适合哪些任务？
- 人物身份、宠物花纹、商品 Logo 和文字的一致性如何？
- 支持哪些分辨率、时长、格式、并发和文件上限？
- 是否支持随机种子、参考图、局部重绘和任务复现？
- 任务失败是否收费，异步任务如何查询和取消？
- 是否有频率限制、地区限制或高峰降级？
- 供应商更新模型后，旧工作流是否保持可用？
- 能否固定模型版本，还是会静默升级？
- 服务故障时是否能导出在途结果并切换供应商？

测试必须使用固定基准集，不能只凭制作人员对少量案例的主观印象。

## 8. 准入评分

每项 0–5 分：

| 维度 | 权重 | 0 分示例 | 5 分示例 |
|---|---:|---|---|
| 数据与隐私 | 25% | 训练、保留和删除均不清楚 | 有明确书面政策、可控训练、有限保留和删除能力 |
| 权利与商用 | 20% | 商用权利不明或禁止交付 | 当前方案明确支持所需商用和分发场景 |
| 安全与账号 | 15% | 个人共享账号、无日志 | 企业权限、MFA、独立密钥、审计和费用限制完善 |
| 输出质量 | 20% | 基准集无法达到最低线 | 稳定达到质量线，缺陷可预测且可修复 |
| 稳定与可控 | 10% | 无版本控制、频繁失败 | 状态可查、回调可靠、模型或工作流可控 |
| 成本与效率 | 10% | 成本不可预测、失败仍高额收费 | 成本透明，可设预算，单位合格产物成本合理 |

计算方法：`总分 = 各项得分 ÷ 5 × 权重之和 × 100`

建议结论：

- 85–100：可在明确能力范围内批准；
- 70–84：限制场景批准，设置额外人工复核；
- 55–69：只允许低风险内部试用；
- 低于 55：不进入生产；
- 数据、权利或安全任一项为 0：无论总分多少均不批准真实用户订单。

评分不能代替法律、安全和隐私负责人对高风险问题的否决权。

## 10. 建议审批状态

### 测试中

- 仅使用合成素材；
- 不接入正式订单；
- 有明确测试期限和负责人。

### 允许低风险订单

- 允许 L1 宠物、非识别文本或其他批准场景；
- 不处理人物、声音和 L3；
- 全量人工质检。

### 允许指定场景

- 明确列出主体、用途、账号、接口和数据处理条件；
- 超出矩阵范围自动阻断；
- 设置较短复审周期。

### 全面允许

- 仅指注册能力和已批准场景范围，不代表任何输入均可使用；
- 仍需订单级授权、风险审核和质量检查。

### 暂停

- 不再接收新任务；
- 评估并处理在途任务；
- 保留调查所需审计证据。

### 禁用

- 撤销账号、密钥和工作流路由；
- 处理供应商侧数据删除；
- 完成账务及合同收尾。

## 11. 工具复审触发条件

除定期复审外，出现以下情况立即复审：

- 服务条款、隐私政策或训练设置发生变化；
- 账号方案从企业版降为个人或团队版；
- 供应商推出或替换主要模型；
- 输出权利、商用许可或内容政策变化；
- 数据处理地区或子处理方变化；
- 发生安全、隐私、侵权或大规模服务故障；
- 质量通过率明显下降或单位成本明显上升；
- 工具开始处理新主体、新用途或更高风险等级；
- 团队改变接入方式，例如从网页手工操作转为 API。

复审期间可把工具降级为 `degraded` 或 `suspended`，不能等结论出来后再阻断风险调用。

## 12. 员工使用规则

- 每位生产人员使用独立企业成员账号，不共享密码；
- 账号必须开启多因素认证；
- 不在个人电脑、网盘、邮件或聊天软件长期保存用户素材；
- 不把用户素材复制到未登记的新工具试效果；
- 不在公开社区、Prompt 分享网站或个人作品集中发布订单内容；
- 不将用户姓名、电话、地址等无关信息写入 Prompt；
- 人工下载原始照片时选择业务原因，任务完成后按规则清理；
- 发现错误上传、账号异常或疑似泄露时立即停止处理并报告，不自行删除证据；
- 工具给出的权利或安全结论只作辅助，不能替代审核记录。

员工违反工具使用规则时，应暂停其素材访问权限并由负责人复核相关订单。

## 13. 密钥与环境规则

- 开发、测试、生产使用不同项目和密钥；
- 移动 App 不包含供应商 API 密钥，所有调用从服务端发起；
- 密钥保存在专用密钥系统，不写入源码、日志或工单；
- 按供应商和工作流拆分密钥，设置权限、预算和频率上限；
- 密钥定期轮换，人员离职、疑似泄露或供应商停用时立即撤销；
- 供应商回调验证签名、时间戳、来源和重放；
- 测试环境不得复制真实用户素材，除非取得明确测试授权并采用与生产相同的保护。

## 16. 首轮盘点执行步骤

1. 列出目前所有实际使用的 AI 和后期工具，包括员工个人试用工具；
2. 按网页端、API、账号方案拆分条目；
3. 暂停所有未登记工具处理新用户素材；
4. 为 GPT、Grok 及主要图像/视频工具分别填写单工具评估表；
5. 先批准非识别文本整理和 L1 宠物等低风险能力；
6. 人物、未成年人、声音和商用场景单独作结论；
7. 建立生产工具白名单和系统级阻断；
8. 设置季度定期复审及条款变化即时复审；
9. 用统一测试集持续记录质量、成本和失败率；
10. 每月淘汰重复、不可控或单位合格成本过高的工具。

## 17. 首轮盘点输出

团队最终应形成四份内部结果：

- **工具总表**：现用、测试、暂停和禁用工具；
- **场景矩阵**：每个工具能处理哪些数据和订单；
- **账号权限表**：谁能访问、调用、下载和管理费用；
- **退出预案**：每个核心能力的备用工具和人工方案。

在这四份结果完成前，最安全的运营方式是：文本工具只接收去标识需求；真实人物照片仅进入经过书面审查的企业级生产工具，并由人工审核和质检全程兜底。
