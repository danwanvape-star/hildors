# 角色之门：核心页面与交互规格（V1）

## 1. 设计目标

本规格承接“正版角色个性化、原创角色定制、未签约IP许愿”三路径，重点解决：

- 用户能否迅速理解平台可以做什么；
- 能否在上传和付款前判断角色是否可制作；
- 能否在普通视频预览之外感知真实设备效果；
- AI与人工协作是否让用户感到可靠，而不是流程漫长；
- 首次交付能否沉淀为持续成长的角色资产。

核心任务应在5个主步骤内完成：

```text
1 找到角色 → 2 确认形象 → 3 赋予行为 → 4 设备预览 → 5 确认并开启角色之门
```

授权、素材补充和人工审核作为条件步骤出现，不应让所有用户经过同样长度的流程。

## 2. 全局页面结构

每个步骤固定显示：

- 当前角色缩略图和名称；
- `第X步 / 共5步`；
- 自动保存状态；
- 当前预计价格区间；
- 返回与继续按钮；
- `为什么需要这些信息？`说明入口；
- 人工协助入口，但不使用即时客服承诺。

退出时保存草稿。用户再次进入时显示：

> 你的角色还在门前，继续完成剩余步骤。

## 3. 第一步：找到角色

### 3.1 页面目的

确认角色身份、作品来源与权利路径，不要求用户理解版权术语。

### 3.2 正版角色路径

标题：**你想唤醒哪位角色？**

页面组件：

- 搜索作品或角色；
- 最近浏览；
- 当前可用角色；
- `已获官方授权`标识；
- 支持的设备和地区；
- 基础包起始价格；
- 可用形象版本数量。

角色搜索结果必须区分：

- `可以立即定制`；
- `即将开放`；
- `尚未授权，可以许愿`；
- `所在地区暂不可用`。

不要让不可购买角色使用与可购买角色相同的主按钮。

### 3.3 原创角色／手办路径

标题：**你的角色目前是什么形态？**

选项：

- 完整角色设定图；
- 只有一张角色图片；
- 实体手办；
- 3D模型；
- 文字概念；
- 品牌吉祥物。

选择后立即显示：

- 推荐素材数量；
- 可达到的效果级别；
- 预计人工参与程度；
- 价格区间；
- 是否可以直接下单或需要免费预审。

示例：

| 输入 | 可达效果 | 下一步 |
|---|---|---|
| 完整三视图 | 高一致性，可制作复杂动作 | 进入上传 |
| 单张图片 | 背面和遮挡区域需要合理补全 | 先选择补全方式 |
| 六角度原创手办 | 可保留材质或进行角色活化 | 进入拍摄引导 |
| 合规3D模型 | 需检查骨骼、材质和许可 | 上传技术预检 |
| 文字概念 | 需要先完成形象设计 | 购买角色设计阶段 |

### 3.4 疑似第三方IP处理

检测提示：

> 这个形象可能来自现有游戏、动漫或品牌。我们会先查找可用的正版版本；如果尚未开放，你可以提交角色愿望。现在不会收取制作费。

按钮：

- `查找正版版本`
- `说明这是我的原创角色`
- `提交角色愿望`

选择“原创”后要求用户提供原创过程或授权证据，不以一项勾选直接放行。

## 4. 第二步：确认形象

### 4.1 正版角色形象

标题：**选择TA来到桌面时的样子**

只展示授权范围内选项：

- 经典版；
- 舞台版；
- 节日版；
- 已拥有的服装；
- 限定配色。

每张卡展示：正面动态缩略预览、是否包含在基础包、额外价格和可用期限。

禁止自由上传其他作品服装作为换装参考。

### 4.2 原创角色基准

标题：**先确定角色身份证**

用户需要确认：

- 正面、侧面和背面；
- 身体比例；
- 主要颜色；
- 发型、脸部与眼睛；
- 必须保留的服装和配件；
- 武器或尾巴等附属结构；
- 可以由制作人员补全的区域。

使用“锁定细节”交互：用户最多标记5个不可改变的细节，并在图上点击对应位置添加短说明。

示例：

- `右眼下方的星形标记必须保留`
- `武器长度不能缩短`
- `裙摆内层必须是蓝色`

确认按钮：`确认这个形象，开始制作动作`

按钮上方提示：

> 确认后，修复形象不一致免费；主动更换服装、发型或角色比例可能需要重新报价。

### 4.3 比较体验

基准确认提供：

- 原始参考；
- 制作基准；
- 设备模拟；

三种视图切换。差异较大的区域由制作人员标记，不允许用低透明度叠图替代可理解说明。

## 5. 第三步：赋予行为

### 5.1 页面目的

不让用户面对抽象Prompt，而是通过可预览的行为组件组装角色。

标题：**你希望TA怎样陪伴你？**

### 5.2 桌面性格

使用四组有限选项：

- 活跃程度：安静 / 均衡 / 活跃；
- 待机气质：可爱 / 酷 / 优雅 / 搞怪；
- 主动频率：偶尔 / 适中 / 经常；
- 夜间模式：安静待机 / 自动休眠。

用户调整后，右侧角色预览即时切换对应待机片段。

### 5.3 首个行为包

推荐默认包含：

1. 初次见面；
2. 呼吸和环顾；
3. 整理服装或装备；
4. 招牌动作；
5. 一段唱跳或音乐表演；
6. 一个低频惊喜动作。

每个动作卡显示：

- 3–5秒静音预览；
- 完整时长；
- 是否循环；
- 是否需要音乐授权；
- 占用空间；
- 基础包内或加购价格；
- 适配设备。

### 5.4 自定义动作

入口文案：`没有想要的动作？描述给制作师`

结构化字段：

- 动作目的：待机 / 舞蹈 / 战斗 / 欢迎 / 节日 / 展示；
- 动作参考：文字、用户有权使用的视频或动作捕捉；
- 持续时间；
- 是否循环；
- 道具；
- 音乐；
- 必须发生和禁止发生的事项。

提交后展示`需要人工评估，不会立即扣费`。

### 5.5 声音与音乐

首发仅开放：

- 无声音；
- 平台已授权音乐；
- IP方提供的官方声音片段；
- 用户原创且通过权利审核的音乐。

不提供原配音演员声音克隆，也不允许用户上传流行歌曲后直接商用制作。

## 6. 第四步：设备预览

### 6.1 页面目的

把“视频好看”转换为“放进设备也好看”。

标题：**看看TA真正来到桌面的样子**

### 6.2 预览模式

- 黑暗房间；
- 普通桌面光线；
- 明亮环境；
- P20和P11尺寸切换；
- 正面和侧面观看角度；
- 原始大小与用户可调大小。

### 6.3 风险提示

系统自动说明：

- 深色部分可能与黑场融合；
- 半透明薄纱或发丝可能在设备上减弱；
- 快速动作可能出现拖影；
- 过细武器和饰品可能不清楚；
- 角色过大可能被安全区裁切。

风险提示必须同时提供解决按钮，如：

- `增强轮廓光`
- `放慢动作`
- `缩小至安全区`
- `交给制作师优化`

### 6.4 技术信息

折叠区显示：

- 内容包大小；
- 设备剩余空间；
- 预计下载与传输时间；
- 固件兼容性；
- 离线是否可播放。

主页面不要突出编码、帧率和码率。

## 7. 第五步：确认与开启角色之门

### 7.1 订单摘要

标题：**确认TA来到你身边的方式**

摘要必须展示：

- 角色名称与来源；
- 正版、原创或公版再设计标签；
- 形象版本；
- 行为包和加购动作；
- 声音与音乐；
- 目标设备；
- 许可用途；
- 制作方式；
- 预计交付时间；
- 包含修改次数；
- 价格明细；
- 退款与取消规则。

### 7.2 许可摘要

使用六个问题说明，不只放协议链接：

- 可以安装到几台设备？
- 可以重新下载多久？
- 可以发到社交平台吗？
- 可以用于直播、展会或门店吗？
- 可以继续购买或委托新动作吗？
- 授权结束后已交付内容怎样处理？

### 7.3 CTA文案

正版即时内容：`购买并唤醒角色`

需要制作的原创角色：`确认订单并开始制作`

需要人工报价：`提交评估，不立即扣费`

未授权IP：不显示支付按钮，只显示`提交愿望并关注进度`。

## 8. 制作中的订单页

### 8.1 状态表达

用户看到的阶段：

```text
素材与权利检查
→ 角色基准制作
→ 等待你确认
→ 动作制作
→ 人工修复与设备适配
→ 真机质检
→ 可以验收
```

每个阶段显示：

- 已完成内容；
- 当前负责人类型：系统 / 制作师 / 用户；
- 预计更新时间；
- 是否影响交付时间；
- 用户需要执行的唯一下一步。

不要展示Grok、GPT或其他供应商名称，也不展示“模型正在思考”。

### 8.2 人工介入触发

以下情况自动转人工：

- 疑似第三方IP或权利冲突；
- 多张参考图角色细节不一致；
- 手部、面部、武器或尾巴连续生成失败；
- 用户锁定细节无法稳定保持；
- 快速动作在设备模拟中失败；
- 用户连续两次反馈同一质量问题；
- 音乐、配音或动作参考权利不清。

人工介入不额外收费的范围：为达到已确认规格所需的修复和设备适配。

## 9. 验收页面

标题：**角色已经准备好穿过大门**

展示顺序：

1. 真实设备录制或标明模拟的预览；
2. 角色基准与成品一致性对照；
3. 每个动作单独播放；
4. 内容包、许可和设备信息；
5. 验收或反馈。

反馈不使用空白文本框作为唯一入口。先选择：

- 形象与基准不一致；
- 动作异常或穿模；
- 画面闪烁、破损或边缘问题；
- 设备显示效果不佳；
- 声音或同步问题；
- 我改变了原来的需求。

前五项进入质量修复；最后一项进入变更报价。

## 10. 首次唤醒仪式

首次安装不是普通进度条，而是产品的情感高潮。

流程：

```text
检测设备
→ 检查空间和兼容性
→ 传输角色核心
→ 安装行为包
→ 完成设备校验
→ 屏幕熄暗
→ 角色播放“初次见面”
→ 用户为角色设置昵称
→ 生成角色护照
```

进度文案示例：

- `正在建立角色核心…`
- `正在带入TA的动作与记忆…`
- `角色已到达设备，准备见面。`

失败时保留已传输数据并显示可恢复步骤，禁止让用户从付款重新开始。

## 11. 角色护照主页

首屏只保留四项：

- 当前角色与在线设备；
- `让TA出现`主按钮；
- 当前待机状态；
- 下一个可解锁事件或内容。

二级内容：

- 已拥有服装；
- 行为与音乐包；
- 陪伴天数和纪念事件；
- 安装设备；
- 继续定制；
- 许可与下载；
- 删除云端源素材。

复购入口优先使用角色上下文：

- `为TA增加一个雨天待机动作`
- `解锁本角色的舞台服装`
- `制作你们的100天纪念动作`

避免只显示泛化的“购买更多内容”。

## 12. 页面状态清单

每个页面至少设计：

- 初始状态；
- 加载状态；
- 空状态；
- 检测失败；
- 网络中断；
- 权利不确定；
- 需要补充素材；
- 地区不可用；
- 设备不兼容；
- 草稿恢复；
- 服务端结果延迟；
- 人工处理中。

## 13. 埋点事件

```text
gate_opened
source_path_selected
character_searched
licensed_character_found
unlicensed_character_wished
input_type_selected
asset_upload_started
asset_quality_issue_shown
rights_precheck_submitted
character_baseline_viewed
character_baseline_approved
behavior_pack_configured
custom_action_requested
device_preview_started
device_preview_risk_resolved
quote_viewed
order_submitted
revision_requested
delivery_approved
device_install_started
device_install_completed
first_awakening_completed
character_passport_viewed
second_content_purchased
```

事件必须携带`source_path`、`rights_status`、`device_model`和`character_type`，但不得记录用户自由文本、图片内容或不必要的敏感信息。

## 14. P0开发优先级

### 必须有

- 来源三路径分流；
- 正版角色搜索和状态；
- 原创角色免费预审申请；
- 角色基准确认；
- 固定行为包配置；
- 设备模拟预览；
- 订单摘要和许可摘要；
- 制作时间线；
- 验收分类反馈；
- 设备安装和失败恢复；
- 首次唤醒；
- 角色护照基本页。

### 可以人工运营替代

- 原创角色报价；
- 权利证据审核；
- 角色基准制作；
- 自定义动作评估；
- 真机质检记录；
- 许愿角色归并。

### 暂不做

- 任意IP即时生成；
- 用户选择生成模型；
- 无限制Prompt；
- 自动声音克隆；
- 全自动原创角色交付；
- 开放式创作者接单市场；
- 实时3D对话角色。

## 15. P0验收标准

内部测试用户应能：

1. 在30秒内判断自己属于哪条角色路径；
2. 在未付款前知道角色是否可制作；
3. 看懂普通视频效果与设备效果的差别；
4. 在5分钟内完成一个正版角色配置；
5. 清楚知道交付内容、许可、工期和修改规则；
6. 在安装失败后从失败节点恢复；
7. 首次播放后在角色护照中找到继续互动与扩展入口。
