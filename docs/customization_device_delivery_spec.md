# Hildors 定制视频设备交付与 P20/P11 验证规范

## 1. 当前能力结论

根据现有项目代码与协议映射：

- P20 对外沿用 P11 通信协议，App 通过局域网 TCP 连接；
- 默认设备地址为 `192.168.4.1:8900`；
- 已有视频列表 `0x36`、指定播放 `0x35`、删除 `0x32/0x33`、重命名 `0x34`、排序 `0x38` 等命令封装；
- 协议定义了视频上传命令 `0x31`，但当前 `P20CommandSession` 尚未实现真实文件上传；
- 当前 App 视频页只能读取列表、指定播放和删除，尚无手机文件选择、格式检查、上传进度、取消、续传和完整性校验；
- 当前协议尚未提供已确认的存储总量/可用空间查询；
- 上传最后一包、续传、哈希校验、取消命令、超时和错误码仍需厂家及真机确认。

因此，定制业务可以先完成云端交付和手机下载，但在 `0x31` 上传协议完成真机验证前，不应对用户承诺“一键传入设备”已经可用。

## 2. 交付链路分层

必须把以下三个阶段建模为独立任务：

1. **云端成品准备**：转码、打包、校验并发布至用户素材库；
2. **下载到手机**：从云端下载设备文件并进行本地哈希校验；
3. **传入设备**：连接 P20/P11，通过局域网发送文件并由设备确认保存。

任一阶段成功不能推断下一阶段成功。例如云端下载完成不代表设备已收到，TCP 数据发送完成也不代表设备已保存。

## 3. DeviceProfile 配置

设备规格不得散落在 App 或生产脚本中，统一使用版本化配置：

```text
DeviceProfile
  id
  product_model              // P20 | P11
  hardware_revision
  firmware_min / firmware_max
  protocol_version
  screen_width / screen_height
  orientation
  safe_area
  background_mode            // black | transparent | other
  container_formats
  video_codecs
  pixel_formats
  frame_rates
  max_bitrate
  max_duration
  max_file_size
  audio_codecs
  audio_sample_rates
  file_name_rules
  max_video_count
  upload_chunk_size
  upload_timeout
  supports_resume
  supports_hash_verify
  supports_storage_query
  status
  version
```

每个设备包锁定 `DeviceProfile` 版本。设备参数更新后只影响新打包任务，不静默改变已交付文件。

## 4. 必须向厂家确认的参数

### 4.1 视频播放参数

- 支持的封装格式，例如 MP4 或其他格式；
- 视频编码、Profile、Level 和像素格式；
- 物理屏幕与素材分辨率、横竖方向和旋转规则；
- 支持的帧率及可变帧率兼容性；
- 建议及最大码率、单文件大小和时长；
- 是否支持透明通道；若不支持，黑底阈值和色彩要求；
- 色彩空间、色深、全范围/限范围和 HDR 支持；
- 是否必须含音轨，无声视频允许无音轨还是静音音轨；
- 音频编码、声道、采样率和码率；
- 首帧、关键帧间隔、快速启动等要求；
- 是否支持循环元数据，或完全由设备播放模式控制。

### 4.2 文件与存储

- 文件名编码是否为 UTF-8；
- 允许的字符、扩展名、最大字节长度和重名行为；
- 最大视频数量；现有 App 查询逻辑当前最多读取 50 个，需确认协议上限；
- 总容量、可用容量、保留空间和空间不足错误码；
- 删除或覆盖文件时是否立即释放空间；
- 断电或上传中断是否会留下临时文件；
- 设备是否对文件自行校验和索引，索引完成需要多久。

### 4.3 `0x31` 上传协议

- 开始上传时的数据结构：文件名、总长度、包数、哈希等；
- 数据包是否包含完整协议帧；
- 包序号宽度、起始值、乱序和重复包处理；
- 推荐和最大分包大小；
- 最后一包真实长度表达方式；
- 每包应答还是窗口式应答；
- 超时、重试次数和限速要求；
- 是否支持查询已接收偏移量及断点续传；
- 是否存在显式取消命令；
- 最终成功是“数据接收完成”还是“文件落盘并可播放”；
- 是否返回 CRC32、SHA-256 或其他完整性校验；
- 完整错误码表以及哪些错误可重试；
- 上传期间是否允许其他控制命令并发；
- 设备重启、Wi-Fi切换、低电量和播放状态对上传的影响。

## 5. 建议设备包结构

云端交付可以使用 Hildors 包封装；传入设备时只发送设备需要的媒体文件。

```text
package-root/
  manifest.json
  cover.jpg
  preview.mp4
  device/
    P20/
      action_p01_v1.mp4
    P11/
      action_p01_v1.mp4
```

`manifest.json` 示例字段：

```json
{
  "schemaVersion": 1,
  "packageId": "pkg_xxx",
  "characterId": "chr_xxx",
  "orderId": "ord_xxx",
  "actionTemplateId": "P01",
  "contentVersion": 1,
  "licenseType": "personal",
  "createdAt": "ISO-8601",
  "files": [
    {
      "deviceModel": "P20",
      "deviceProfileVersion": 1,
      "path": "device/P20/action_p01_v1.mp4",
      "size": 0,
      "sha256": "...",
      "durationMs": 0,
      "width": 0,
      "height": 0,
      "videoCodec": "TBD",
      "audioCodec": "TBD"
    }
  ]
}
```

`TBD` 参数在厂家确认前不能作为生产默认值。

## 6. 文件命名建议

设备文件名应使用稳定、短小、仅 ASCII 的技术名称，用户显示名称保存在 App/云端元数据中。

建议格式：

`HD_{characterShortId}_{actionId}_{version}.{ext}`

示例：`HD_A7F3_P01_01.mp4`

规则：

- 不在设备文件名中写入用户真实姓名、电话或订单号；
- 不使用空格、中文、表情或路径特殊字符，直至厂家确认兼容性；
- 文件名冲突时不静默覆盖，先查询设备列表并让用户选择替换或保留两个版本；
- 显示名称与物理文件名分离，例如设备文件 `HD_A7F3_P01_01.mp4` 在 App 显示“球球·向你挥手”。

## 7. 云端打包校验

发布设备包前必须自动完成：

- 文件可以完整解码；
- 容器、视频/音频编码、像素格式符合 `DeviceProfile`；
- 分辨率、方向、帧率、码率、时长和大小不超限；
- 不包含设备不支持的多音轨、字幕、章节或额外数据流；
- 首尾帧、黑底/透明区域和显示安全区符合动作模板；
- 文件 SHA-256 与清单一致；
- 文件名符合字符和长度限制；
- 对每个目标型号分别生成结果，不能用“理论兼容”代替验证。

任一检查失败时设备包状态为 `invalid`，不能进入用户素材库。

## 8. 手机下载任务

任务状态：

`queued → downloading → verifying → ready`

异常状态：`paused`、`network_error`、`storage_error`、`hash_mismatch`、`expired`、`cancelled`。

规则：

- 下载前检查手机可用空间，至少保留文件大小加解包临时空间；
- 支持 HTTP Range 时断点续传，否则明确重新下载；
- 下载链接短期有效，过期后使用登录态重新申请；
- 下载完成必须按 manifest 校验文件大小和 SHA-256；
- 校验失败的文件不能进入可传输状态；
- 连接设备热点导致互联网断开时，已完成下载不受影响；未完成下载应暂停而非误报失败或成功。

## 9. 设备传输状态机

```text
preparing
  → checking_connection
  → checking_compatibility
  → checking_storage
  → negotiating_upload
  → transferring
  → device_verifying
  → indexing
  → completed
```

异常状态：

- `device_disconnected`
- `incompatible_device`
- `unsupported_firmware`
- `insufficient_storage`
- `transfer_timeout`
- `device_rejected`
- `checksum_failed`
- `index_failed`
- `cancelled`
- `unknown_result`

`unknown_result` 用于手机已发完数据但没有得到设备最终确认的情况。此时不得显示成功，应重新连接并查询视频列表或上传结果。

## 10. 传输前检查

按顺序执行：

1. 本地文件状态为 `ready` 且哈希有效；
2. P20 控制连接为已连接；
3. 查询设备型号、硬件版本、固件版本和协议能力；
4. 匹配设备包中的 `DeviceProfile`；
5. 查询文件列表并检查重名；
6. 查询可用空间；协议未支持前，不得向用户承诺精确空间检查；
7. 检查设备电量与充电状态；协议未支持前显示能力不可用，不模拟数值；
8. 检查当前是否有其他上传任务；
9. 与用户确认替换、保留版本或取消；
10. 创建本地持久化传输任务。

## 11. 传输执行规则

- 同一设备同一时刻只允许一个文件上传；
- 上传期间控制命令是否串行，以厂家协议结论为准；未知时暂停非必要控制命令；
- 每包保存序号、偏移、发送时间、重试次数和设备应答；
- 进度以设备确认的字节数计算，不能只按 Socket 已写入字节计算；
- App 进入后台时遵守平台限制，并向用户说明是否能继续；
- 断线后保留任务和已确认偏移；支持续传时恢复，不支持时从头开始；
- 用户取消时发送协议取消命令；协议没有取消能力时停止发送，并提示设备可能残留临时文件；
- 最后一包完成后等待设备落盘、哈希和索引结果；
- 最终查询视频列表，确认目标文件存在且可被指定播放。

## 12. 传输成功定义

只有同时满足以下条件才能标记 `completed`：

1. 所有数据包被设备确认；
2. 设备返回最终文件保存成功；
3. 完整性校验通过；
4. 文件出现在设备视频列表；
5. 对首发测试阶段，执行指定播放成功并完成可视检查。

如果旧协议只能确认部分条件，App 应显示“文件已发送，等待设备确认”或“结果待确认”，而不是“传输成功”。

## 13. 重名与版本

发现同名文件时提供：

- 替换现有版本；
- 作为新版本保留；
- 取消传输。

替换流程建议：

1. 上传临时文件名；
2. 校验和索引成功；
3. 删除旧文件；
4. 重命名新文件为正式名称。

如果设备不支持安全替换或空间不足以同时保留两个文件，必须向用户说明风险，不能先删除旧文件再尝试未验证的新上传。

## 14. 设备异常与用户提示

| 异常 | 用户提示重点 | 恢复动作 |
|---|---|---|
| 未连接设备 | 文件仍保存在手机 | 进入连接引导 |
| 型号不兼容 | 当前文件没有此型号版本 | 申请重新转码 |
| 固件过旧 | 说明最低固件版本 | 引导升级或联系支持 |
| 空间不足 | 展示所需空间和设备内容入口 | 删除内容后重试 |
| 低电量 | 传输可能中断 | 充电后继续 |
| Wi-Fi 断开 | 已下载文件不会丢失 | 重连并续传/重传 |
| 校验失败 | 损坏文件不会播放 | 自动重试一次后转人工 |
| 设备拒绝 | 显示可理解的错误类别 | 依据错误码修复 |
| 结果未知 | 不重复盲目上传 | 重连查询文件列表 |

## 15. 实机测试矩阵

至少覆盖：

| 维度 | 测试值 |
|---|---|
| 设备 | P20、兼容 P11、不同硬件批次 |
| 固件 | 最低支持版本、当前版本、待升级版本 |
| 网络 | 设备 AP、路由局域网、弱信号、断开重连 |
| 文件 | 最小、常用、接近上限、超限、损坏 |
| 名称 | 短 ASCII、最大长度、重名、非法字符 |
| 视频 | 无声、有声、循环、不同帧率和码率边界 |
| 存储 | 充足、接近不足、不足、删除后重试 |
| 电量 | 充足、低电量、充电中、传输中断电 |
| App | 前台、锁屏、后台、被系统终止、重新启动 |
| 协议 | 正常、超时、重复应答、错误包、最后包异常 |

每次测试记录设备序列/批次、固件、App 版本、文件哈希、协议日志、耗时、结果和故障视频。

## 16. 首发验收用例

- [ ] 合格设备包能下载、校验、传入并播放；
- [ ] 不合格编码在云端打包阶段被阻止；
- [ ] 手机存储不足时不开始下载；
- [ ] 云端下载中断能够恢复或清晰重试；
- [ ] 设备型号或固件不兼容时不开始上传；
- [ ] 文件重名不会发生静默覆盖；
- [ ] 设备空间不足时保留手机文件和任务；
- [ ] 传输断开后不会误报成功；
- [ ] 最后一包不是标准包长时仍能正确保存；
- [ ] 重复包不会生成重复或损坏文件；
- [ ] App 重启后能恢复未完成任务；
- [ ] 设备最终校验失败时自动重试不超过规则上限；
- [ ] 传输成功后文件出现在列表并可指定播放；
- [ ] 删除手机缓存不会删除云端和设备文件；
- [ ] 订阅取消不会删除 P20/P11 中已交付的视频。

## 17. 实现优先级

### P0：协议验证

- 获取厂家完整 `0x31` 定义和错误码；
- 确认视频、音频、文件名和容量参数；
- 用一个固定测试文件完成开始、分包、最后包、保存和播放；
- 验证中断、重复包、超时、空间不足和断电。

### P1：App 上传闭环

- 本地文件校验；
- 持久化传输任务；
- 单文件上传、进度、取消和失败恢复；
- 最终列表与播放确认；
- 用户可理解的错误映射。

### P2：定制素材库整合

- DeviceProfile 和设备包；
- 云端下载及哈希；
- 型号匹配与重新转码；
- 多版本、重名和安全替换；
- 订单、素材和设备安装状态联动。

## 18. 当前阻塞项

现阶段最关键的外部阻塞不是 AI 生成质量，而是设备上传协议未闭环。需要厂家或硬件团队明确：

1. `0x31` 完整报文及最后一包规则；
2. 设备最终保存和完整性校验应答；
3. 中断续传与取消能力；
4. 存储空间查询及空间不足错误码；
5. 支持的视频、音频和文件名规格。

在这些参数确认之前，首发动作可以生成预览和云端成品，但设备正式文件只能标记为“待设备规格确认”。
