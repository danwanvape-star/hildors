# Hildors 首发定制动作库（V1）

## 1. 设计原则

首发动作应优先满足四个条件：

- 主体始终处于全息显示安全区；
- 动作幅度可控，不依赖复杂手部、道具和多人互动；
- 容易保持人物五官、宠物花纹和体型一致；
- 能自然循环或停留在稳定结尾，适合设备持续播放。

首发不追求大量动作。建议先稳定完成 5 个人物动作和 5 个宠物动作，再根据真实订单质量扩充。

## 2. 通用视频模板

| 项目 | V1 规则 |
|---|---|
| 画面方向 | 根据 P20/P11 实际屏幕比例读取设备模板 |
| 时长 | 标准动作建议 5–8 秒，可由后台配置 |
| 镜头 | 固定镜头为主，禁止快速推拉、旋转和大幅摇移 |
| 主体范围 | 全身或大半身，关键部位不得超出安全区 |
| 背景 | 优先使用设备要求的纯黑背景或透明方案 |
| 循环 | 优先首尾自然衔接；不适合循环时使用稳定停留结尾 |
| 声音 | 默认无声；音乐和音效作为独立选项 |
| 输出 | 编码、分辨率、帧率和码率由设备配置模板生成 |
| 预览 | 用户预览应保持相同构图，可降低分辨率并添加水印 |

设备安全区、黑位、透明通道、编码和最大码率必须通过实机测试确定，不在动作模板中写死。

## 3. 人物首发动作

### P01 自然站立与挥手

- 用户名称：**向你挥手**
- 场景：欢迎、陪伴、日常展示
- 构图：全身，人物面向镜头，居中站立
- 动作：自然呼吸 → 单手缓慢挥动 2–3 次 → 回到自然站姿
- 建议时长：6 秒
- 循环：可循环，首尾均为自然站姿
- 难度：低
- 建议点数：1 点
- 风险点：手指畸形、手臂穿过身体、挥手速度过快、脸部随动作漂移
- 验收：手掌数量及方向正确，脸部一致，脚部不滑动，首尾姿态接近

### P02 微笑点头

- 用户名称：**微笑回应**
- 场景：陪伴、问候、桌面展示
- 构图：膝上或半身，面向镜头
- 动作：自然表情 → 轻微微笑 → 缓慢点头一次 → 回到自然表情
- 建议时长：5 秒
- 循环：可循环
- 难度：低
- 建议点数：1 点
- 风险点：牙齿变化、夸张表情、五官漂移、头发抖动
- 验收：身份一致，表情自然，点头幅度小，头发和配饰稳定

### P03 左右轻摆

- 用户名称：**轻松律动**
- 场景：音乐播放、氛围陪伴
- 构图：全身，双脚保持在安全区
- 动作：身体轻微向左、向右摆动，手臂自然跟随
- 建议时长：6 秒
- 循环：必须自然循环
- 难度：低至中
- 建议点数：1 点
- 风险点：脚底漂移、腰部扭曲、服装边缘闪烁
- 验收：重心合理，脚底稳定，衣服轮廓连续，循环无明显跳变

### P04 比心

- 用户名称：**送你一颗心**
- 场景：礼物、纪念、亲友互动
- 构图：半身或大半身
- 动作：双手从自然位置抬起，在胸前完成比心，停留后恢复
- 建议时长：6–7 秒
- 循环：可循环
- 难度：中
- 建议点数：1 点；复杂手势不稳定时可配置为 2 点精修版
- 风险点：手指数量、双手融合、手部遮挡脸部、衣服穿模
- 验收：手势清晰，手指无明显畸形，双手未融合，脸部无遮挡且稳定

### P05 鞠躬致意

- 用户名称：**感谢有你**
- 场景：感谢、欢迎、活动结束
- 构图：全身，人物正面站立
- 动作：自然站立 → 缓慢鞠躬 → 短暂停留 → 起身
- 建议时长：6 秒
- 循环：以自然站姿首尾衔接
- 难度：中
- 建议点数：1 点
- 风险点：躯干比例变化、头部与身体脱节、脚底滑动、头发穿模
- 验收：躯干结构正常，起身后身份未变化，脚部稳定，衣服和头发自然

## 4. 宠物首发动作

### A01 坐姿呼吸与眨眼

- 用户名称：**安静陪伴**
- 场景：桌面常驻、夜间陪伴
- 构图：宠物全身坐姿，正面或轻微侧面
- 动作：自然呼吸、眨眼、耳朵轻动
- 建议时长：6 秒
- 循环：必须无感循环
- 难度：低
- 建议点数：1 点
- 风险点：眼睛数量变化、耳朵形状漂移、毛发闪烁、花纹变化
- 验收：关键花纹稳定，眼睛和耳朵动作自然，身体无位移，循环平滑

### A02 抬爪打招呼

- 用户名称：**抬爪问好**
- 场景：欢迎、互动
- 构图：坐姿全身，抬起一只前爪
- 动作：自然坐姿 → 缓慢抬爪 → 停留 → 放下
- 建议时长：6 秒
- 循环：可循环
- 难度：低至中
- 建议点数：1 点
- 风险点：爪子数量、左右爪切换、腿部融合、身体体型变化
- 验收：抬爪方向一致，四肢数量正确，身体和毛色稳定

### A03 开心摇尾

- 用户名称：**开心见到你**
- 场景：回家欢迎、活力展示
- 构图：站姿或坐姿全身，尾巴完整可见
- 动作：头部轻抬、尾巴左右摆动、身体轻微响应
- 建议时长：6 秒
- 循环：必须自然循环
- 难度：低至中
- 建议点数：1 点
- 风险点：尾巴数量或长度变化、尾巴穿过身体、花纹漂移
- 验收：尾巴连接位置正确，摆动自然，身体轮廓和花纹稳定

### A04 歪头好奇

- 用户名称：**好奇歪头**
- 场景：互动、可爱表达
- 构图：坐姿半身或全身，面向镜头
- 动作：注视镜头 → 头部缓慢向一侧倾斜 → 眨眼 → 恢复
- 建议时长：5 秒
- 循环：可循环
- 难度：低
- 建议点数：1 点
- 风险点：脸型变化、双眼不一致、耳朵错位、脖颈拉伸
- 验收：脸部和耳形保持一致，倾斜角度自然，颈部无畸变

### A05 趴下休息

- 用户名称：**安心休息**
- 场景：睡眠陪伴、安静氛围
- 构图：全身，预留身体降低所需空间
- 动作：站姿或坐姿 → 缓慢趴下 → 眨眼或闭眼停留
- 建议时长：7–8 秒
- 循环：不强制循环；可单向播放后停留
- 难度：中
- 建议点数：1 点；姿态复杂时允许升级人工精修
- 风险点：四肢融合、身体长度变化、落地漂浮、毛色和花纹变化
- 验收：趴下过程结构合理，四肢位置可信，最终姿势稳定无漂浮

## 5. 暂缓动作

首发不建议把以下动作放入标准 1 点模板：

- 奔跑、跳跃、翻滚、快速舞蹈；
- 双手精细手势、拿取小物品、乐器演奏；
- 人与宠物或多人拥抱、牵手、身体接触；
- 复杂口型同步或长句讲话；
- 大幅旋转、背身再转回正面；
- 服装快速变化、变身和复杂特效；
- 商品拆解、液体飞溅、精细文字动态展示；
- 需要真实物理碰撞的动作。

这些需求统一进入自定义动作评估，按 2 点或以上、人工精修或项目报价处理。

## 6. 标准动作参数对象

后台建议使用以下结构管理动作，而不是写死在 App：

```text
ActionTemplate
  id
  version
  subject_type              // person | pet | product
  display_name
  description
  preview_asset_id
  base_points
  duration_range
  loop_mode                 // seamless | end_hold | non_loop
  framing
  motion_prompt_template_id
  negative_prompt_template_id
  device_profile_ids
  risk_level
  required_source_views
  qa_rule_set_id
  status                    // draft | internal | active | paused | retired
  created_at / published_at
```

动作模板发布新版本后，已下单任务继续使用需求快照中锁定的旧版本。暂停模板只阻止新订单，不应静默改变在途交付。

## 7. 动作选择页规则

每个动作卡展示：

- 名称和标准示例；
- 适合场景；
- 时长范围；
- 是否循环；
- 所需点数或价格；
- 对照片角度的额外要求；
- “示例仅展示动作和构图，最终角色以你的角色基准为准”。

如果用户素材不满足动作要求，系统应提示补充照片或选择其他动作，不能先收取点数再告知无法制作。

## 8. 自定义动作评估表

自定义动作提交后不立即扣点，由制作人员评估：

| 维度 | 低 | 中 | 高 |
|---|---|---|---|
| 动作幅度 | 小范围站立/坐姿 | 行走、转身、蹲起 | 跳跃、翻滚、快速舞蹈 |
| 手脚精细度 | 无精细动作 | 简单手势/抬爪 | 手指操作、拿小物体 |
| 主体数量 | 1 | 2 | 3 个以上 |
| 互动接触 | 无 | 简单并排 | 拥抱、牵手、碰撞 |
| 镜头 | 固定 | 缓慢移动 | 快速运镜、多镜头 |
| 声音 | 无声/音乐 | 短音效 | 口型、真人声音 |
| 特效 | 无 | 简单光效 | 变身、粒子、复杂合成 |

- 全部为低：可按 1–2 点处理；
- 任一为中：至少 L2，2 点起；
- 任一为高：L3 或项目报价，不承诺标准工期；
- 制作可行性不足时应拒绝或建议替代动作，不通过反复生成碰运气。

## 9. 动作级质检

除通用 100 分质检外，每个动作必须检查：

- 起始姿态是否与模板一致；
- 动作顺序和方向是否正确；
- 主体是否始终在安全区；
- 关键肢体、尾巴、配饰和道具是否连续；
- 动作是否达到用户可感知程度，且不过度夸张；
- 循环动作的首尾位置、光线和轮廓是否衔接；
- 结束停留是否足够稳定；
- 同一订单多条动作之间角色是否一致。

标准动作不合格时优先使用模板缺陷码，不要求质检员每次自由描述。

## 10. 缺陷原因码

```text
ID_DRIFT                 主体身份或形象漂移
FACE_DEFORM              五官或脸部畸变
LIMB_ERROR               肢体数量、结构或运动错误
PAW_ERROR                宠物爪部错误
TAIL_ERROR               尾巴数量、连接或运动错误
PATTERN_DRIFT            宠物毛色/花纹漂移
LOGO_TEXT_ERROR          Logo 或商品文字错误
CLOTHING_FLICKER         服装/配饰闪烁
BACKGROUND_ARTIFACT      背景破损或杂物
FOOT_SLIDE               脚底滑动
FRAME_OUT                主体越出显示安全区
LOOP_JUMP                循环首尾跳变
MOTION_MISMATCH          动作与模板不符
AUDIO_SYNC               音画不同步
DEVICE_SPEC              设备规格不合格
CONTENT_POLICY           内容安全或权利问题
```

原因码可多选，并关联出现时间和截图。工作流效果统计以原因码为基础，而不是只统计“生成失败”。

## 11. 模板上线流程

1. 产品和制作提出动作模板；
2. 使用合成或已授权的测试角色完成至少 10 次生成；
3. 覆盖人物/宠物不同体型、毛发、服饰和设备画面；
4. 记录首次通过率、平均尝试次数、人工工时和设备播放结果；
5. 质检负责人确认规则和致命缺陷；
6. 商业负责人根据完全成本确定点数和价格；
7. 发布为 `internal`，只供内部订单；
8. 达到阈值后发布为 `active`；
9. 错误率上升、工具变化或投诉集中时转为 `paused`；
10. 新版本重新走测试，不覆盖旧订单。

## 12. 模板上线指标建议

每个标准模板至少持续监控：

- 素材满足率；
- 首次生成通过率；
- 两轮内通过率；
- 平均 AI 成本；
- 平均人工修复时长；
- 内部质检缺陷分布；
- 用户首次验收通过率；
- P20/P11 传输和播放成功率；
- 用户选择率和重复购买率。

标准模板的目标不是“AI 能生成”，而是能在可预期的成本和时限内稳定交付。
