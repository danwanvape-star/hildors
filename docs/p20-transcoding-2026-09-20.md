# P20 转码接入第二阶段

## 已实现

- `p20_ffmpeg_preparation.dart`：按已有取景定义缩放、平移、黑底填充和裁剪，输出 298×298 RGB24、20fps。A 路径提取 MP3；B 仍由上一阶段编排直接跳过音频。原视频不覆盖。
- `p20_bin_encoder.dart`：移植厂家 C# 的环形采样、行列方向、149 LED 中心掩码、跨帧亮度系数；输出 960 行×160 列 JPEG 帧、小端时长、两帧黑屏、1600 字节前缀和 4 字节对齐记录。输出虽由通讯协议命名为 MP4，实际仍是设备专用容器。
- `p20_mobile_media_engine.dart`：Android/iOS FFmpeg 原生适配，参数以数组传递，不拼接 shell。仅取消当前会话；原生启动/完成等待有时限。超时或取消后未确认原生退出时不删除临时目录、不允许复用会话。
- 视频容器编码在 isolate 执行。临时目录独立创建；正常结束由调用方 dispose 清理；取消删除未完成容器，原素材保留。

## 依赖与平台

新增并锁定 `ffmpeg_kit_flutter_new_audio 2.5.2`；现有 `image 4.9.2` 从间接依赖转为直接依赖，未升级其他现有包。音频版包含所需 LAME，维护方声明 LGPL-3.0 且不含 GPL 编码组件；正式发布仍需完成依赖许可证材料核对。[包维护方说明](https://pub.dev/packages/ffmpeg_kit_flutter_new_audio)

本机 Android debug 构建通过，证明原生依赖能被 Gradle 集成，不代表手机运行测试通过。构建提醒该插件仍使用旧 Kotlin Gradle Plugin，未来 Flutter 升级需再检查。iOS 工程最低版本当前为 15.0，高于依赖声明的 14.0；未在 Mac 上构建或签名。

## 实际验证

- 最终 55 项目标测试通过：包含原有协议/播放列表回归，以及新增映射、容器、音频缺失、取景参数、取消、原生回调缺失、文件保留测试。
- 新增实现及测试的静态检查无问题。
- 真实桌面 FFmpeg 测试：生成 320×180、25fps、含 AAC 的 0.2 秒合成视频，经取景滤镜转换后生成 20fps 设备文件，时长头为 200ms；输出 MP3 为双声道、16kHz。测试在执行后清理合成文件。
- 上一阶段已验证厂家 `17k` 请求实际由桌面 LAME 编成 16kbps；手机版本实际输出还须探测。
- 独立审查指出取消后等待原生回调可能无限挂起，已复现并修复，增加启动挂起、完成回调丢失及未停止时保留临时文件的测试。

## 与参考代码的边界

298×298、20fps 是用户明确规格。扫描角数 960 依据厂家代码固定矩阵行数，仍需厂家有效设备文件/真机核验。C# 原有亮度共享变量存在并行竞争，移植采用确定性的最小值；跨帧保留系数及降 JPEG 质量时使用未缩放图像的行为予以保留。

JPEG 使用 Dart image 编码器而非 OpenCV；虽然结构、尺寸及采样方式匹配，不能声称二进制字节完全一致或硬件兼容已验收。音画同步、旋转素材、非方形像素素材、长视频性能仍需实测。

原始 RGB 中间文件限制 512 MiB，达到限制明确失败，不静默交付截断视频。此次未把完整中间视频载入内存，但手机磁盘占用及转码耗时尚未测量。
