# P20 App 上传接入（0.1.50 / 51 联调版）

后续规则修正：A、B 均支持无声视频；以下“A 无音轨失败”为 0.1.50 历史行为，0.1.51 已修正，详见 `p20-silent-video-2026-09-20.md`。

## 已实现

- Dashboard 与独立控制页使用 2026-09-20 协议。原客户端保留显式旧协议模式；不按超时自动猜测固件版本。
- 控制、列表查询和上传共用一个串行 TCP 连接。上传期间不会把其他指令写入文件数据；连接关闭会更新 UI，取消上传会主动断开且停止自动重连。
- 空闲连接持续检测 EOF；测试覆盖断线通知、上传确认、超时后拒绝排队指令和单连接顺序。
- A/B 列表查询、播放、删除、排序包含 LIST_ID；中文文件名采用 GBK 字节编码，拒绝不匹配的列表应答。新增依赖 [gbk_codec 0.4.0](https://pub.dev/packages/gbk_codec)，未升级其他依赖。
- 播放列表的待处理视频进入取景页后，可进入上传页面。A：提取音轨 MP3 → 转码 → 上传 MP3 → 上传视频；B：仅转码和上传视频。298×298、20fps，使用已调整的缩放和平移。
- A 视频没有音轨会明确失败，不生成背景音乐。远程 URL 要求先通过原有授权下载流程下载到本地，不在设备上传页直接下载。
- 转码显示阶段提示；上传百分比来自设备确认，不把转码时间伪装为进度。原视频不修改，独立临时文件结束后清理；仍被原生任务占用时保留。
- 上传完成写回对应本地列表并移除待处理项。列表刷新失败但设备已确认视频成功时保留成功结果，避免重复上传。普通返回、系统返回都保留结果。
- 页面准备阶段销毁后不会继续处理；取消、音频成功但视频失败均显示独立状态，不擅自删除设备文件。

## 用户验收

1. 在手机连接 P20 Wi-Fi，在 App 首页连接设备。
2. 进入播放列表 A，导入一段短的带音轨视频，调整取景后点击“转码并上传”。验证音频先于视频上传，完成后回到列表播放。
3. 同样视频加入 B，确认没有提取或上传音频阶段，并由外接蓝牙提供音频。
4. A 无音轨、处理中取消、上传时断网、上传完成按系统返回，分别检查提示、原文件和列表。
