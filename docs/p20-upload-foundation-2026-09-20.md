# P20 音视频上传基础模块验收

## 用户确认

- 预处理画面 298×298，20 帧/秒，保留现有取景参数。
- A 日常列表：提取音频 → 转码视频 → 传 MP3 → 传视频 → 刷新。
- B 蓝牙联动列表：转码视频 → 传视频 → 刷新；不提取、不上传音频。
- A 无音轨明确提示，不自动添加音乐。

## 本次实现

新增 `p20_v2_protocol.dart`：2026-09-20 固件累加校验、流式帧解码、列表编号及大端文件大小、GBK 字节结构/长度与文件名验证。编码器接收已经编码的 GBK 字节，尚未加入任意中文字符串到 GBK 的转换依赖。

新增 `p20_v2_connection.dart`：独占 Socket、全局串行操作、32 KiB 流式上传、尾块完成应答、确认序号校验、超时及取消关闭连接、设备拒绝码。它是新版固件专用连接，禁止与旧客户端同时连接同一设备。

新增 `p20_media_upload_flow.dart`：A/B 编排、单次尝试、失败阶段及部分成功记录、取消检查。设备基础文件名使用 ASCII 标识符（GBK 子集），与用户展示标题分离。媒体处理器和设备目标通过接口注入，尚未安装手机编码器或接通 App 页面。

## 验证

目标测试覆盖新旧协议、播放列表、A/B 顺序、无音轨、音频失败、视频失败、取消、超时、设备拒绝及真实本机 TCP 字节传输。模拟 TCP 测试对 1、32768、32769、65536 字节逐字节核对，确认查询排在上传之后。

独立代码审查指出准备阶段取消缺口，已增加取消契约与回归测试。尚未覆盖实际设备、Android/iOS 媒体编码器、弱网及全部异常固件应答。

桌面 FFmpeg 对合成音频执行厂家的 `-ac 2 -ar 16000 -c:a libmp3lame -b:a 17k`，ffprobe 实测 MP3 双声道、16000 Hz、16000 bit/s。17k 是请求参数，实际编码器选择 16kbps；手机编码器还需验证。合成媒体仅存在本地 output，未加入 Git。

## 实施裁定与未完成项

Ruling: 新增独立新版模块，不直接切换旧 UI 客户端。原因：旧固定校验协议仍有调用方，完整的列表命令适配和手机编码器尚未接通；现在切换会破坏现有功能。代价：本次交付不能在 App 上执行新上传。

Ruling: 在共享工作区仅新增独有文件，不修改其他任务已有文件；没有复制或回滚未提交改动。

用户提供的尺寸/帧率已解决这两项参数疑问。仍需核对厂家参考构造参数及前处理 `P20TranscodeAsync` 的完整实现，或用厂家有效设备文件确认转码方向、亮度、黑帧及音画同步。当前没有宣称转换输出已兼容。

后续必须完成：手机音频/视频适配器与临时文件生命周期、GBK 中文显示名称转换、双列表命令/UI接入、本地化、取消资源释放、有效转码样例比较、真机验收。接口注释中的尺寸帧率不等于已实现编码。
