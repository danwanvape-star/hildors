# Hildors 第一阶段战略：互动全息收藏品平台

## 1. 战略定位

- **主定位**：下一代互动全息收藏品平台。
- **第一场景**：动漫/游戏角色桌面化。
- **第一功能**：唱跳、待机、音乐联动和角色记忆。
- **第一商业模式**：硬件 + 正版角色内容包 + 创作者市场。

Hildors不是“上传照片生成视频”的AI工具，也不只是全息播放器。它把用户喜欢的正版虚拟角色变成可以放在桌面上、持续互动、不断获得新内容的数字收藏品。

## 2. 战略变化

### 更符合当前能力

现有App和P20协议围绕本地视频、指定播放、播放模式、亮度、角度和蓝牙音频展开。正版角色包可以直接建立在“设备本地视频 + App内容管理”之上。

### 更容易解释用户价值

“把喜欢的角色放到桌面上”比“AI定制服务”更直观。硬件形成入口，角色内容带来持续复购。

### 更适合规模化

官方内容可预制、审核和适配，不需要每个订单都经过照片审核、AI生成、人工返工和用户验收。

### 降低首发风险

第一阶段不收集用户人脸和声音，不提供真人克隆。主要治理对象转为IP授权、内容分级、创作者权利和AI透明度。

## 3. 第一阶段不做

- 真人或宠物照片视频定制；
- 未成年人照片定制；
- 真人声音克隆；
- 用户选择GPT、Grok或其他内部模型；
- 开放Prompt生成并直接发布；
- 无审核UGC市场；
- 复杂实时3D和动作捕捉；
- 依赖云端的实时设备控制；
- 创作者上传后立即售卖；
- 没有IP证明的动漫/游戏角色。

原有照片定制规则保留为第二阶段的高客单增值服务。

## 4. 核心用户

### 首要用户

- 动漫、游戏和虚拟角色收藏用户；
- 喜欢桌搭、手办、RGB和桌面设备的用户；
- 愿意为正版角色和高质量表演付费的人群；
- 已购买数字皮肤、DLC、虚拟偶像内容或收藏品的人群。

### 次要用户

- 动画、舞蹈、MMD、Cosplay和视觉创作者；
- IP方、游戏发行商、虚拟偶像和音乐厂牌；
- 游戏房、动漫店、展会和品牌活动。

## 5. 商业飞轮

```text
优质正版角色内容
  → 提升设备购买理由
  → 增加设备用户
  → 吸引更多IP方和创作者
  → 增加内容供给与复购
  → 提高设备活跃与平台收入
```

## 6. 产品三层结构

### 设备层

- P20/P11连接和状态；
- 内容安装、删除、排序和播放；
- 亮度、角度和播放模式；
- 蓝牙音乐输入与状态；
- 本地离线播放；
- 设备与固件兼容。

### 角色内容层

- 官方角色页和角色内容包；
- 唱跳、待机和音乐联动动作；
- 服装、歌曲、主题和活动版本；
- 购买、下载、安装和授权；
- 角色收藏柜和当前角色。

### 平台层

- IP授权与官方发行；
- 创作者入驻、资质和角色授权；
- 内容提交、审核、适配和发布；
- 销售、分成、退款和下架；
- 盗版投诉与权利追踪；
- 内容推荐、活动和收藏关系。

## 7. 第一功能

### 待机

待机是一组预制角色状态：基础呼吸、眨眼、环顾、整理服装、坐下休息和低频惊喜动作。V1使用视频池和本地随机/顺序调度，不需要实时生成。

### 唱跳

- 正版角色动作视频；
- 对应合法授权音乐；
- 内容包明确歌曲、长度和使用范围；
- 音视频本地同步播放；
- 首发优先短表演和循环段落。

### 音乐联动

第一阶段分两级：

1. 状态联动：音乐开始、暂停和断开时切换角色视频；
2. 节奏联动：后续按音量、节拍或频段切换动作。

新版蓝牙状态协议尚未完全确认，V1先提供预制音乐氛围视频和手动选择，协议确认后再开放自动联动。

### 角色记忆

V1不是大模型聊天记忆，只保存收藏与陪伴状态：

- 首次激活日期和累计陪伴天数；
- 最近播放和喜欢的动作；
- 当前服装、主题和角色昵称；
- 解锁的纪念动作；
- 设备安装记录。

不记录私密对话，不推断人格，不上传蓝牙音频内容。

## 8. 正版角色内容包

基础包建议包含：

- 角色封面、作品来源和版权方；
- 3–5条待机动作；
- 1条欢迎动作；
- 1条招牌动作；
- 1条音乐或舞蹈内容；
- 设备版本、文件哈希和AI来源信息；
- 用户许可、销售地区、销售期和下架规则。

可售SKU：角色基础包、歌曲/舞蹈包、服装主题包、节日包、限定收藏包、双角色包和硬件联名预装包。

购买规则：

- 已购买并交付的内容在许可范围内继续本地使用；
- 云端重新下载期限和兼容设备须购买前说明；
- 合同到期后的下载和已购使用权必须在IP合同中预先约定；
- 不因会员结束远程删除已安装内容；
- 退款、欺诈、法律要求或安全召回作为明确例外处理。

## 9. IP授权包

每个角色发布前建立`RightsPackage`：

```text
rights_holder
licensed_character
territories
sales_channels
devices
content_types
music_and_voice_scope
commercial_term
sell_through_period
user_license
creator_derivative_rights
ai_generation_permissions
marketing_permissions
reporting_and_royalty
takedown_rules
post_expiry_user_access
```

必须确认：

- 是否允许AI辅助制作；
- 是否允许创作者制作衍生动作；
- 是否允许角色与音乐、服装或其他角色组合；
- 可销售地区、设备和渠道；
- 合同终止后已购用户能否继续使用和下载；
- 版权方品牌规范和终审流程；
- 宣传截图、短视频和直播展示范围。

用户购买的是使用许可，不获得角色IP所有权。

## 10. 创作者市场

### 首发模式

采用邀请制、审核制市场，不开放即时UGC发布。

创作者可以：

- 为平台自有或已签约IP制作动作；
- 使用官方资产和品牌规范；
- 提交原创角色及权利证明；
- 制作不含受限角色的通用特效和背景。

创作者不能：

- 上传未授权动漫、游戏或名人角色；
- 从游戏中提取模型、音乐或动画销售；
- 使用无商用权的模型、素材、字体或音乐；
- 使用用户照片或他人作品作为未授权训练/参考资产；
- 上传成人色情、仇恨、欺诈、政治冒充或未成年人不当内容。

### 发布流程

```text
创作者申请
  → 身份、税务、收款和作品审核
  → 选择官方授权项目 / 提交原创权利
  → 获取角色规范和设备模板
  → 制作与本地预检
  → 上传内容、工程证据和AI工具声明
  → 自动技术校验
  → 内容、IP和质量人工审核
  → 必要时版权方终审
  → 定价、地区、分成和发布日期确认
  → 发布与持续监控
```

用户支付金额应拆分税费/渠道费、IP版税、创作者分成、平台收入和退款准备金。比例按项目配置，不承诺全球统一分成。

## 11. 审核规则

### 权利

- 创作者身份和收款主体；
- 原创或授权证明；
- 角色、音乐、声音、字体、动作捕捉和素材来源；
- AI工具及商用条款；
- 地区、销售期限和设备范围。

### 内容

- 色情、未成年人、仇恨、暴力和自残；
- 欺诈、冒充、错误代言和误导；
- 政治人物和敏感公共事件；
- 不符合角色设定或版权方品牌规范；
- 高频闪烁、过强音量和不适运镜。

### 技术

- 编码、分辨率、帧率、码率和时长；
- 黑底/透明、循环和安全区；
- 哈希、恶意文件和包结构；
- P20/P11实机播放；
- AI机器可读标记和披露。

## 12. 来源标签

- `Official`：IP方或Hildors官方发布；
- `Licensed Creator`：批准创作者在授权项目中发布；
- `Original Creator`：创作者原创角色；
- `AI-assisted`：使用AI生成或显著编辑；
- `Human-made`：声明主要由人工制作；
- `Device verified`：通过指定设备测试。

`Human-made`不能隐藏局部AI使用，最终标签由平台依据制作记录确定。

## 13. 内容状态

```text
draft
  → rights_review
  → technical_review
  → content_review
  → licensor_review
  → approved
  → scheduled
  → published
```

异常状态：`changes_required`、`rejected`、`paused`、`region_blocked`、`delisted`、`rights_expired`、`recalled`。

下架只停止新销售；召回可能影响下载或设备内容，只有违法、欺诈、安全或合同等明确依据才能执行。

## 14. 购买与安装闭环

1. 浏览角色和动作预览；
2. 查看版权方、创作者、价格、设备、地区、大小和许可；
3. 购买或兑换；
4. 服务端确认支付并写入权益；
5. 下载对应设备包；
6. 校验哈希与兼容性；
7. 连接P20/P11；
8. 检查空间、固件和重名；
9. 传输、设备校验和索引；
10. 指定播放并加入待机池；
11. 更新角色记忆和安装记录。

购买、下载、安装和播放是四个独立状态。

## 15. 第一阶段MVP

### P0

- 1台可稳定安装内容的P20目标设备；
- 3个权利完整的首发角色；
- 每个角色1个基础包；
- 每包包含待机、欢迎、招牌和音乐内容；
- 内容商城、详情、购买/兑换和素材库；
- 下载、校验、安装和播放；
- 角色收藏柜和当前角色；
- 本地待机播放策略；
- 简单角色记忆；
- IP/内容审核后台；
- 地区销售、版本和下架；
- 支付、退款和售后。

### P1

- 蓝牙状态触发角色视频；
- 更多服装、歌曲和节日包；
- 限定编号和收藏徽章；
- 角色记忆云同步；
- 邀请创作者；
- 销售、分成和版权方报表。

### P2

- 节奏分析和动作切换；
- 多角色互动；
- 原创角色开放市场；
- 动态角色事件；
- AI对话和更深记忆；
- 照片定制作为高级服务。

## 16. 首发内容组合

- 1个Hildors原创角色，验证完整链路；
- 1个小型但社群活跃的独立游戏/虚拟角色；
- 1个音乐或舞蹈属性强的角色，验证唱跳价值。

不应一开始追求大量顶级IP。所有角色都要有明确的设备、销售、营销、AI辅助和用户持续使用授权。

## 17. 核心指标

首发北极星指标：

**每台已激活设备30天内成功安装并播放的正版付费角色内容包数量。**

辅助指标：

- 设备激活率和首包安装成功率；
- 7日/30日设备活跃；
- 每台设备拥有的角色包数量；
- 每月内容收入/活跃设备；
- 待机、唱跳和音乐联动播放占比；
- 下载、安装和播放成功率；
- 角色包复购间隔；
- 创作者提交到发布周期；
- IP投诉、技术退回和退款率。

## 18. 风险控制

| 风险 | 控制 |
|---|---|
| 正版IP不足 | 先做原创角色和独立IP合作 |
| 被认为只是视频播放器 | 用角色收藏、待机池、记忆和持续内容形成差异 |
| 上传协议不稳定 | 优先闭环`0x31`和实机安装 |
| 内容包过大 | 短动作、分包、增量更新和规格控制 |
| 盗版进入市场 | 邀请制、权利证明、人工审核和投诉下架 |
| 合同到期影响用户 | 预先约定sell-through和post-expiry access |
| 音乐授权成本高 | 短表演、自有/定向授权音乐或无音乐动作 |
| 角色记忆引发隐私 | V1只存收藏行为，不记录对话和推断人格 |
| 蓝牙协议不足 | 先手动音乐模式，确认协议后自动化 |
| AI透明度 | 来源声明、机器标记、人工审核和地区披露 |

## 19. 90天路线

### 1–30天：可播放的正版角色

- 闭环`0x31`上传、存储、校验和播放；
- 确定原创角色和两个合作候选；
- 完成内容包、设备模板和权利模板；
- 制作首个角色基础包；
- App完成商城、详情、素材库和安装原型。

### 31–60天：购买与陪伴

- 接入支付和内容权益；
- 完成设备安装和失败恢复；
- 实现待机池和V1角色记忆；
- 完成地区、AI披露、退款和售后；
- 30–50名种子用户试用。

### 61–90天：验证复购和供给

- 为首发角色增加歌曲/服装/节日包；
- 邀请5–10名创作者；
- 完成提交、审核、定价和分成后台；
- 观察内容购买、播放和设备活跃；
- 决定是否扩大IP、创作者和音乐联动。

## 20. 最终战略判断

第一阶段的核心不是“让用户生成任意角色”，而是：

> 让用户购买设备后，能在10分钟内安装一个真正喜欢、权利清晰、表现稳定的角色，并愿意持续购买该角色的新内容。

照片定制保留为平台成熟后的高客单增值服务，不作为首发商业闭环的主入口。
