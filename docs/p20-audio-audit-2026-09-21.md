## 参数逐项对照

| 厂商参数 | 含义及App核对 |
| --- | --- |
| -y | 覆盖临时输出；App在独立临时目录内输出，不覆盖用户源视频 |
| -i 输入路径 | 使用参数数组传给原生会话，无需手工拼接引号；中文和空格路径真实测试通过 |
| -map 0:a:0 | 只选第一条音轨，不混合多音轨；双音轨样本测试与厂商命令输出相同 |
| -vn | 不输出视频流 |
| -ac 2 | 输出双声道；真实ffprobe核对为2 |
| -ar 16000 | 采样率16000Hz；真实ffprobe核对一致 |
| -c:a libmp3lame | MP3编码器；真实输出codec_name=mp3 |
| -b:a 17k | 请求17kbps，保持厂商值；当前桌面FFmpeg实际输出bit_rate=16000，厂商原命令同样为16000，不误报实际为17kbps |
| .mp3输出 | 临时音频文件；上传时与视频使用相同basename、不同扩展名 |

App额外传入-hide_banner、-loglevel error、-nostdin控制日志与交互，不改变音频参数。本次同一FFmpeg、同一双音轨输入下，App生成MP3与直接执行厂商指令生成MP3逐字节完全相同。这是特定环境和样本的证据，不代表所有FFmpeg版本生成字节均一致。

## 无音轨及上传流程

- 提取前用ffprobe确认第一音轨存在；确认没有音轨才返回P20MissingAudio。
- 无音轨源在A列表只转换和上传视频；损坏文件/编码失败不能冒充无音轨继续上传。
- A有声顺序：提取MP3→视频转码→确认音频上传→上传视频→刷新列表。
- B接受有声或无声源视频，按用户明确的“不读取声音”规则跳过音频提取与上传。
- 音频上传失败停止后续视频上传；音频成功但视频失败保留已传音频标识，不自动重复或删除设备文件。
- 原生封装检查返回码；失败、取消、超时分别处理；仅确认原生任务结束才清理工作目录。

## 未验证边界

厂商指令没有规定音量归一化、音轨起始偏移、音频长于视频时裁切、无声素材补静音等策略。当前实现不擅自增加这些处理。尤其视频容器两帧引导黑屏与MP3编码延迟是否由固件补偿，需要真机音画同步测试。
