# HILDORS 后台 MVP 实施蓝图

日期：2026-09-14。状态：可评审的实施方案，尚未部署后台或购买云资源。

## 1. 业务边界与首版目标

Android、iOS共用业务接口和账号权益；员工通过Web后台管理内容与定制订单。手机通过局域网控制P20/P11，云服务不参与实时播放指令。两套硬件列表由蓝牙状态自动切换，云端不能假定已有列表写入能力。

第一条上线链路：运营发布真实视频包 → 用户浏览/领取 → 我的角色选择单视频 → 下载校验 → 设备适配 → 局域网上传确认。转码和列表写入以厂家实际能力为准。

定制是首版后台核心模块：需求、素材、报价、制作任务、审核、版本确认、受控交付。公开创作者自助入驻、分账和推荐算法放在后续阶段。MythBuild不接入目录、账号或下载接口。

## 3. 数据模型与状态归属

| 实体 | 核心字段/关系 | 约束 |
|---|---|---|
| characters | id、名称、创作者、来源 | 角色身份独立于视频文件 |
| packages | id、character_id、标题 | 首版一个角色一个主包；可支持后续扩展包 |
| package_versions | package_id、版本、发布时间 | 发布后不可覆盖，更新创建新版本 |
| clips | id、名称、时长 | 播放列表选择的最小单位 |
| package_clips | package_version_id、clip_id、顺序 | 一个包包含多条视频；独立视频不必伪造角色 |
| media_variants | clip_id、用途、设备规格、字节数、sha256、storage_key | 原片/手机预览/硬件版分别保存；目录不返回存储密钥或永久URL |
| tags/content_tags | 类型、标签、内容关联 | 来源、形式、题材三个筛选维度独立 |
| favorites | user_id、内容ID | 收藏只表达偏好，不授予付费权益 |
| entitlements | user_id、目标ID、来源、有效期、状态 | 免费领取、购买、定制交付分别记录；服务器裁定 |
| devices/device_bindings | 型号、标识、用户、绑定状态 | 注册设备不等于证明设备所有权；强绑定依赖厂家验证机制 |
| customization_orders | 用户、状态、需求版本、报价版本、交付包 | 制作、支付、退款状态分别保存 |
| payment_events | 渠道、外部交易ID、事件ID | 唯一约束防止重复发放权益 |
| audit_events | 操作者、动作、对象、时间 | 发布、退款和权限变更可追溯 |

“我的角色”聚合已收藏、已领取和已交付内容，卡片明确可用状态。收藏未领取的内容先取得合法权益；包内只展示真实可用视频。

四种状态不能互相替代：

- 收藏：服务端偏好记录，可跨手机同步。
- 权益：服务端授予使用资格，移除收藏不撤销购买。
- 已下载：当前手机文件存在且校验通过，不随账号同步假装另一手机已有文件。
- 已安装：指定设备确认存在相应文件；本机标记和上传进度100%都不足以证明。

设备离线时显示上次验证时间。厂家不支持查询的状态显示未知，不推断成功。离线已获准内容按明确的离线许可策略使用；设备无法验证许可时，不能承诺硬件级防复制或实时撤销。

## 4. 首版接口契约范围

基础路径 `/v1`。下表是接口设计范围，不表示接口已上线。

| 接口 | 作用 |
|---|---|
| GET /bootstrap | 平台/地区/版本/设备能力配置；更新策略 |
| GET /catalog | 游标分页；source、format、tags、query筛选 |
| GET /packages/{id}/versions/{version} | 包、独立视频、可用文件变体和兼容性 |
| GET /me/library | 我的角色聚合；返回收藏与权益，不返回虚假的本机下载状态 |
| PUT/DELETE /me/favorites/{contentId} | 幂等收藏/移除 |
| POST /claims | 免费内容领取；服务端检查是否允许领取 |
| POST /delivery-tickets | 验证权益、地区、设备及文件版本，签发短时凭证 |
| POST /devices/binding-requests | 创建设备绑定请求；按实际设备证明能力确认 |
| POST /customization/orders | 按已确认需求及授权版本创建订单 |
| GET /customization/orders/{id} | 当前状态、下一步、交付与修改版本 |
| POST /customization/orders/{id}/upload-intents | 私有素材直传凭证，限定类型、大小、路径与时效 |
| POST /customization/orders/{id}/submissions | 确认素材完整性与需求版本，提交审核 |
| POST /customization/orders/{id}/approvals | 确认指定成果版本，防止错确认旧版 |
| POST /payments/{provider}/webhooks | 验签、去重、落账，再更新权益 |
| /admin/* | 内容、审核、订单、任务、发布和审计；逐接口校验员工权限 |

写入订单、领取和交付请求带Idempotency-Key；相同键和不同请求体返回冲突。并发更新带版本号，冲突返回409。时间用UTC；金额用最小货币单位整数并带币种。

错误返回稳定code、用户可读message和requestId；不把堆栈、原始Socket异常、密钥或签名地址显示给用户。

交付凭证签发和续签都重新检查权益。下载断开可申请新凭证继续，但本地通过哈希才进入已下载状态。公开预览、可下载内容和定制设备交付采用不同权限。

## 5. 内容与定制任务

内容：draft → processing → review → published → withdrawn。处理失败进入failed并保留原因；重试不直接发布。

素材管线：私有直传 → 文件验证 → 预览与缩略图 → 厂家格式适配 → 质检 → 版本清单 → 审核发布。标准FFmpeg转码不等于厂家专用格式转换。任务队列允许重复投递，worker按任务ID和输入版本去重，失败进入人工可查看的队列。

定制履约：draft → submitted → review → quoted → awaiting_payment → production → customer_review → revision/approved → delivery_ready → completed。拒绝、取消和退款采用明确分支；付款只由服务器可信交易结果确认；用户只能确认成果，不能自行切换生产或交付状态。

定制原始素材私有保存；外部制作方只能访问分配给自己的任务。交付批准后产生包版本与用户权益，不生成公开下载链接。保存期限配置化，删除任务覆盖对象版本、派生文件和供应商副本并记录结果。

## 6. 部署与成本边界

建议首版采用NestJS模块化业务API、PostgreSQL、对象存储/CDN、消息队列、独立媒体worker和React管理后台。具体运行时版本在实施时锁定。Redis按缓存/任务需要增加，不为架构图单独引入组件。

开发、测试、正式环境隔离；测试环境与正式环境的账号数据、存储桶和支付凭证不混用。正式环境按可用性目标配置API实例及数据库高可用，备份必须验证可恢复。

海外首发先选一个主区域和CDN；区域选择依据首发市场、用户素材处理地域和实测网络。预留region字段不等于已实现跨区合规。后续中国区或额外地域采用独立部署和明确的数据边界。

成本分开统计：API/数据库固定成本、存储GB月、CDN流量GB、转码任务时长、AI制作任务、邮件通知。月下载流量估算=活跃下载用户×每人下载视频数×平均文件大小×重下载系数。CDN减少源站负载但不消除流量成本。未确认用量前不提供固定账单承诺。

## 7. App与公司资产管理

Flutter共用业务逻辑，Android/iOS分别维护签名、渠道配置和支付适配。iOS构建安排macOS runner；国内安卓与海外安卓的推送、登录、支付能力通过渠道适配，不能假设所有华为手机支持Google服务。

公司持有代码仓库、云账号、域名、开发者账号和签名资产。员工使用个人子账号和最小权限。CI使用密钥管理，不把生产密钥提交到仓库或放进App。产品版本可以一致，各渠道构建号独立递增。

后台支持地区/平台/渠道配置、兼容版本和功能开关；不得把配置开关当成任意下发代码。支付支持渠道适配，具体数字商品及定制服务的付款方式按商店、地区和实际交付确认，不能统一假设官网收款即可。

发布流程：代码检查 → 构建 → 内部测试 → 验收 → 商店提交 → 分阶段发布 → 监控。App与API向后兼容，数据库采用先新增后迁移的方式；不能依赖回滚App立即修复已发布客户端。

## 8. 实施与验收顺序

| 阶段 | 可交付物 | 验收条件 |
|---|---|---|
| B1 基础 | API工程、数据库迁移、认证、员工权限、测试环境 | 非本人订单无法读取；普通员工无法发布 |
| B2 内容 | 目录、包版本、素材管线、管理后台 | 运营发布一包真实内容，App能查询版本和单视频 |
| B3 我的角色 | 收藏、领取、权益、签名交付、App API适配 | 换手机同步权益；下载状态按本机核验；失效链接不能越权续签 |
| B4 定制 | 订单、私有素材、任务、版本确认和交付 | 一个测试订单走到受控交付；不同用户不能访问素材 |
| B5 商业 | 商店支付验证、退款、订阅及通知 | 重复/乱序回调不重复发权益；取消续费与撤销权益分开 |
| B6 真机 | 厂家SDK、取景参数、上传和设备验证 | 在目标硬件上实际播出；未知结果不显示已安装 |

B1—B4可在厂家接口未完成时推进；B6必须等待实际转码、音频、上传应答和列表写入能力确认。不可因收到超时就盲目重发当前硬件数据包。

迁移规则：保留四个真实Demo；旧本地claimed可导入收藏，但不得变成付费权益；旧onDevice标记须重新查询设备验证；旧待处理引用保留并映射稳定ID；登录前本地数据不自动归属到错误账号。

首轮实现范围建议定为B1+B2，交付可运行的测试后台、数据库迁移和一包内容的发布/读取演示，再对接App。上线云资源、开发者账号和真实支付另按实际环境执行。
